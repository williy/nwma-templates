# NWMA Templates: IT資産価値管理方式 (Net Worth Management Architecture)

> **「SLOの自律維持と、永続資産の保護を設計のゴールとする」**

NWMAは、属人化した設計判断を構造化し、ITシステムを「管理負債」ではなく、継続的に価値を生む「IT資産」として運用するための設計フレームワークです。

## 1. 核心となる設計思想

最新の設計定義と、SLO自律維持の論理的なアプローチについては、公式サイトを参照してください。

* **公式サイト**: [IT資産価値管理方式（NWMA）実務ガイド](https://juicyltd.biz/nwma-manifesto/)

## 2. アーキテクチャの階層定義

NWMAは、以下の3つのレイヤーによってシステムの整合性を自律的に維持します。

* **NWMA (Standard / 設計基準)**: 全体を貫く共通規格。要件（A）・構造（B）・検証（C）をセットで管理し、長期間にわたって「設計意図」を継承できる資産価値を確立します。
* **IWMA (Foundation / 基盤層)**: インフラ基盤。Terraform等を用い、クラウドベンダーの仕様変更や寿命に左右されない、柔軟で堅牢な境界定義を行います。
* **PWMA (Platform / 実行層)**: プラットフォーム。Ansible等を用い、構成ドリフトを抑制し、常に「あるべき状態」への復旧を可能にします。

## 3. リソースの定義と保護原則

NWMAは「計算資源（Vessel）」と「永続資産（Asset）」を論理的に分離する、クリーンなアーキテクチャを推進します。

* **計算資源 (Vessel)**: VMやコンテナなど、ステートレスで再生成可能なリソース層。異常検知時には自動再デプロイによる復旧を前提とします。
* **永続資産 (Asset)**: データベースやストレージなど、保護すべきデータ層。削除保護（Deletion Protection）等を二重に定義し、環境の再生成から隔離・保護します。

## 4. 管理シート：A/B/C Sheets

設計情報を3つの役割に分類し、完全なトレーサビリティを確保します。

| シート名 | 役割 | 成果物 / 対象 |
| --- | --- | --- |
| **A-Sheet (Requirement)** | 設計ポリシーの定義 | SLO定義、要件識別子（A-No）の発行 |
| **B-Sheet (Architecture)** | 構成定義の正本 | IaC (Terraform / Ansible)、アーキテクチャ定義書 |
| **C-Sheet (Verification)** | 妥当性の証明 | 復旧プロトコル動作検証、エビデンス記録 |

## 5. ディレクトリ構造

```text
nwma-templates/
├── A-Sheets/           # 要件定義・設計ポリシーの記録
├── B-Sheets/           # 構成定義と自動適用スクリプト
│   ├── IWMA/           # インフラ基盤定義（Terraform等）
│   └── PWMA/           # プラットフォーム構成（Ansible等）
├── C-Sheets/           # 妥当性検証・障害注入テスト
├── chronicle/          # プロジェクトの意思決定履歴
├── manifesto/          # NWMA基本理念・ガバナンス憲章
└── templates/          # A/B/Cシートの実務テンプレート

```
